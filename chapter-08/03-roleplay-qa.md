# 単元 8-3：技術選定理由・セキュリティ担保の根拠を説明するロールプレイ

> **この単元のゴール**
> 提案の場で出る厳しい質問・反対意見に、**専門用語を使わず、根拠を持って、短く**答えられるようになる。このカリキュラムで学んだすべての知識を、顧客との会話の中で使える形にする。

---

## 【概念の解説】

### 1. 答え方の型：結論 → 理由 → 具体例 → 結論

質疑応答で最も多い失敗は、**前置きが長く、結論がどこにあるか分からない**ことです。次の型（PREP法）で答えます。

| 順番 | 内容 | 例：「なぜ Google のクラウドなのか？」 |
|---|---|---|
| **P**oint（結論） | 一言で答える | 「分析の仕組みと、データの保管を、同じ会社のサービスでまとめられるからです」 |
| **R**eason（理由） | なぜそう言えるか | 「同じ会社にまとめると、つなぎ目が少なくなり、設定のミスが起きにくく、費用も読みやすくなります」 |
| **E**xample（具体例） | 御社に当てはめると | 「御社の場合、毎朝の自動集計から社長のダッシュボードまでが、すべて東京のデータセンターの中で完結します」 |
| **P**oint（結論） | もう一度結論 | 「ですので、安全性と費用の両面で、御社の規模に合っていると考えています」 |

**30秒〜1分で答え終わる**ことを目安にします。相手がもっと知りたければ、追加で質問してくれます。

### 2. 「分からない」ときの答え方

すべての質問に即答できる必要はありません。むしろ、**推測で答えて後から訂正する方が、信頼を大きく損ないます。**

> 「大切なご質問なので、正確にお答えしたいと思います。確認して、明日中にメールでご回答します」

そして、**必ず約束の期限までに回答する**こと。これ自体が、保守運用を任せられる相手かどうかの判断材料になります。

### 3. よくある質問と、答えの骨子

このカリキュラムの各単元の【顧客向け言語化トレーニング】で練習してきた質問に加え、提案の場でよく出る質問の「答えの骨子」を整理します。**丸暗記ではなく、根拠となる単元を思い出しながら、自分の言葉で答えられるようにしてください。**

| 質問 | 答えの骨子 | 根拠の単元 |
|---|---|---|
| 「kintone だけで十分じゃないの？ kintone にも集計機能はあるよね」 | kintone は**入力と日々の業務**に優れている。ただし、他のシステム（販売管理）のデータと合わせた分析、過去との比較、数字の定義の統一は苦手。kintone はそのまま使い続け、その「裏側」に分析の場所を作る | 4-1, 6-1 |
| 「今は ChatGPT みたいな AI に聞けば、分析してくれるんじゃないの？」 | AI は分析の**道具**として強力。ただし、**AI に渡すデータそのものがバラバラ・不正確だと、AI も間違った答えを出す**。正しく整理されたデータの場所を作ることは、AI を活用するための土台にもなる | 3-3, 4-2, 6-4 |
| 「クラウドって、情報漏洩が心配なんだけど」 | 社内サーバーとクラウドのリスクを比較する。漏洩の多くは「設定のミス」と「権限の与えすぎ」から起きる。何重もの鍵、役割ごとの権限、記録を残す仕組みで防ぐ | 1-4, 2-5, 3-5, 5章 |
| 「そちらの会社は小さいけど、何かあったら大丈夫なの？」 | アカウント・データ・プログラムはすべて御社名義・御社の所有。設計書も渡すので、他社への引き継ぎも可能。障害対応の体制と約束（SLA）を明示する | 5-4, 7-4 |
| 「最初は安くても、後でどんどん費用が上がるんじゃないの？」 | 費用の内訳と前提条件、上限を設定する仕組み、超えそうなときの事前の通知、月次報告で使用量を見える化 | 6-2, 7-3 |
| 「現場が新しいものを嫌がるんだけど」 | 現場の入力方法は変えない。現場にとってのメリット（二重入力の解消など）を、後のフェーズで提供する。現場の代表者を設計に巻き込む | 4-1, 8-2 |
| 「導入して、本当に使われるの？ 前に高いシステムを入れて失敗したんだよ」 | 過去の経験に共感する。小さく始め、最初の成果（会議資料作りが不要になる）を短期間で出す。使われているかを数字で確認し、改善を続ける | 6-5, 8-2 |
| 「なぜデータベースを2つ（PostgreSQL と BigQuery）も使うの？」 | 「レジ」と「資料室」を分ける。業務を止めずに分析でき、費用も使った分だけ | 6-1 |
| 「バックアップはちゃんと取ってくれるの？」 | どの時点まで・何時間で戻せるかを数字で。定期的に戻す訓練。攻撃者に消されない場所に保管 | 7-1 |

### 4. 反対意見への向き合い方

反対意見は、**検討が真剣に行われている証拠**です。言い負かすのではなく、その奥にある懸念を理解しようとします。

| ステップ | 例：営業部長「kintone に余計な入力が増えるなら反対だ」 |
|---|---|
| **① 受け止める** | 「おっしゃる通りです。営業の皆さんの入力の負担が増えるのは、絶対に避けるべきだと思っています」 |
| **② 懸念を確認する** | 「入力が増えること以外に、気になっている点はありますか？」（本当の懸念は別にあることも多い：「自分たちの数字が細かく監視されるのでは」など） |
| **③ 事実で答える** | 「今回の仕組みでは、kintone の入力画面も入力項目も一切変わりません。今入力していただいている内容を、裏側で自動的に集めるだけです」 |
| **④ 相手のメリットを示す** | 「むしろ、営業部長が毎月まとめていらっしゃる担当者別の受注状況を、自動で出せるようにしたいと考えています。どんな形で見られると便利か、教えていただけませんか？」 |

### 5. してはいけないこと

| NG | 理由 |
|---|---|
| 専門用語でけむに巻く | 「この人の説明は分からない」＝「任せられない」と受け取られる |
| 「絶対に安全です」「100% 大丈夫です」 | セキュリティに絶対はない。根拠のない断言は、事故が起きたときに信頼を完全に失う |
| 競合他社や前任の業者を悪く言う | 顧客がその業者を選んだ判断を否定することになる |
| 質問の意図を確認せずに答え始める | ずれた答えになる。「〇〇という意味でのご質問でしょうか？」と確認する |
| 長く話しすぎる | 相手の時間を奪う。結論から、短く |

## 【実務・ビジネスとの結びつき】

### これが理解できていないと起きること

| 現場の症状 | 根本原因 |
|---|---|
| 「提案内容は良かったが、質疑応答で信頼を失った」 | 質問に対して結論から答えられず、長く・分かりにくい説明をした |
| 「その場で"できます"と答えたことが、後で大きな負担になった」 | 確認せずに安請け合いした |
| 「反対していた部長を説得しようとして、余計にこじれた」 | 懸念を聞かずに、言い負かそうとした |

### 顧客のどの課題を解決するか

- 経営者は、技術の中身を完全には理解できなくても、「**この人は、分からないことを分かるように説明してくれる**」「**できないことをできないと言ってくれる**」かどうかで、相手を判断している。言語化の力は、技術力と同じくらい、受注と長期の信頼を左右する。

## 【理解度チェック課題】

**Q1.**
PREP 法（結論 → 理由 → 具体例 → 結論）で答えることのメリットを説明してください。また、「なぜ PostgreSQL を使うのか」という質問に PREP 法で答えてください（専門用語を使わずに）。

**Q2.**
質問に即答できないとき、推測で答えるのではなく「確認して後日回答する」方がよい理由を説明してください。

**Q3.**
反対意見に向き合う4つのステップを挙げ、それぞれのステップがなぜ必要か説明してください。

## 【顧客向け言語化トレーニング】

**演習（ロールプレイ：提案の質疑応答）**

講師（Claude）が、**株式会社ミナト部品の社長・営業部長・総務課長**の3役を務めます。単元8-2で作成した提案書を説明した後の質疑応答の場面です。

**進め方**

1. チャットで「単元8-3のロールプレイを始めます」と伝え、単元8-2で作成した提案書（または1ページ要約）を貼り付けてください
2. 講師が、3人の誰かとして質問・反対意見を1つずつ投げかけます（**全部で8問程度**。後半ほど厳しくなります）
3. あなたは、**実際に口頭で話すつもりで**、1問ずつ回答してください（目安：200〜300字程度）
4. 終了後、講師が各回答を次の観点で採点し、改善した回答例を示します

| 観点 | 内容 |
|---|---|
| 結論が先か | 最初の一文で質問に答えているか |
| 専門用語 | 使っていないか、使った場合は説明しているか |
| 根拠 | カリキュラムで学んだ仕組みに基づいているか |
| 誠実さ | 断言しすぎていないか、できないことをできると言っていないか |
| 相手への配慮 | 質問者の立場・懸念を受け止めているか |
| 長さ | 長すぎないか |

> **ヒント**：総務課長は、大手設備メーカーから届いたセキュリティのチェックシートを手元に持っています。「アクセス権限の管理方法」「データの暗号化」「バックアップの頻度と保管場所」「障害発生時の連絡体制」について、具体的に聞かれる可能性があります。
