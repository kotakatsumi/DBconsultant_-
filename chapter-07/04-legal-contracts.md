# 単元 7-4：個人情報保護法、委託契約、SLA の基礎

> **この単元のゴール**
> 顧客のデータ（個人情報を含む）を預かる受託事業者として、**法律上どんな立場になり、何を求められるか**を理解する。契約・SLA で、自分と顧客の責任範囲を明確にできるようになる。

> ⚠️ **この単元は、法律の考え方を理解するための教材であり、法的助言ではありません。** 法律やガイドラインは改正されます。実際の契約や事故対応では、個人情報保護委員会の最新のガイドライン・Q&A を確認し、弁護士などの専門家に相談してください。

---

## 【概念の解説】

### 1. 個人情報保護法の基本用語

| 用語 | 意味 | 例 |
|---|---|---|
| **個人情報** | 生存する個人に関する情報で、特定の個人を識別できるもの | 氏名、氏名と結びついたメールアドレス・電話番号、顔写真 |
| **個人データ** | 個人情報のうち、**データベースなどで検索できるように整理されたもの**に含まれるもの | 顧客管理 DB、kintone の顧客アプリ、Excel の顧客名簿の各行 |
| **要配慮個人情報** | 不当な差別や偏見が生じないよう特に配慮が必要な情報 | 病歴、犯罪歴など。原則として取得に本人の同意が必要 |
| **個人情報取扱事業者** | 個人情報データベース等を事業に使っている者 | **規模に関係なく、ほぼすべての事業者が該当する** |

このカリキュラムで扱うデータ基盤は、**まさに「個人データ」を集約する仕組み**です。法人顧客のデータであっても、担当者の氏名・メールアドレス・電話番号は個人データにあたります。

### 2. 安全管理措置：技術は「4つのうちの1つ」

個人情報取扱事業者は、個人データの漏えいなどを防ぐために、必要かつ適切な **安全管理措置** を講じる義務があります。個人情報保護委員会のガイドラインでは、次のように整理されています。

| 区分 | 内容の例 | このカリキュラムとの対応 |
|---|---|---|
| **組織的** | 責任者の設置、取扱いのルール、事故時の報告体制 | 単元7-2 の障害対応の体制 |
| **人的** | 従業者への教育、秘密保持 | — |
| **物理的** | 入退室管理、機器の盗難防止、廃棄時の消去 | 単元1-3（ファイル削除）、単元1-4（データセンター） |
| **技術的** | アクセス制御、アクセス者の識別と認証、外部からの不正アクセスの防止、漏えい防止 | 第2章・第3章・第5章のほぼすべて |
| **外的環境の把握** | 外国で個人データを取り扱う場合、その国の制度を把握する | 単元6-2（データの保管場所） |

**技術的な対策は重要ですが、4つのうちの1つ**です。顧客への提案では、「技術的な対策はここまで仕組みで担保します。組織的・人的な部分（社内ルール、教育）は、御社と一緒に整えましょう」と、範囲を明確にします。

### 3. 「委託」と委託先の監督

顧客がデータ基盤の構築・保守をあなたに依頼し、その過程で個人データを取り扱わせることは、法律上 **委託** にあたります。委託は「第三者への提供」とは区別され、本人の同意は不要とされています。その代わり、

> **委託元（顧客）は、委託先（あなた）を必要かつ適切に監督する義務を負います。**

つまり顧客は、あなたに対して、

- 安全管理措置の内容の確認（どんなセキュリティ対策をしているか）
- 契約での取扱い条件の取り決め
- 取扱い状況の把握（報告、必要に応じて監査）

を行う必要があります。受託側としては、**これらに応えられる資料と体制を最初から用意しておく**ことが、信頼と受注につながります。

| 用意しておくとよいもの | 中身 |
|---|---|
| セキュリティ対策の説明資料 | 構成図（単元2-5）、権限設計（単元3-5・5-4）、暗号化、監視、バックアップ |
| 個人データの取扱い条件の契約条項（後述） | |
| 事故時の連絡体制と手順 | 単元7-2 |
| 再委託先の一覧 | クラウド事業者の扱い（後述）、他の外注先 |

### 4. 漏えい等が起きたとき

2022年4月の改正法の施行により、一定の漏えい等が起きた場合、**個人情報保護委員会への報告と本人への通知が義務**になりました。

**報告が必要になる主な場合**（個人の権利利益を害するおそれが大きいもの）

1. 要配慮個人情報が含まれる
2. 不正に利用されると**財産的被害**が生じるおそれがある（クレジットカード番号など）
3. **不正の目的**（不正アクセスなど）によるおそれがある
4. 本人の数が **1,000人を超える**

**報告の期限**

| 段階 | 期限の目安 |
|---|---|
| 速報 | 事態を知ってから **速やかに（概ね3〜5日以内）** |
| 確報 | **30日以内**（不正の目的によるおそれがある場合は **60日以内**） |

**委託先で漏えいが起きた場合**、委託先にも報告義務がありますが、委託先が**委託元に速やかに通知した場合**は、委託元が報告することになり、委託先の報告義務は免除される仕組みになっています。つまり、受託者としては、

> **事故（の疑い）を把握したら、直ちに顧客に知らせる**

ことが、法律上も契約上も最も重要な行動です。単元3-5の監査ログと単元7-2の障害対応の体制は、「何件の、どの項目が、いつからいつまで」を特定して報告するための材料になります。

### 5. クラウドと「外国」の論点

Google Cloud のような外国企業のクラウドを使うことは、「外国にある第三者への個人データの提供」にあたるのでしょうか。

個人情報保護委員会の Q&A では、クラウドサービス事業者が**契約上、個人データを取り扱わないこととなっており、適切にアクセス制御を行っている場合**には、個人データの「提供」にはあたらない、という考え方が示されています。ただしその場合でも、**利用する事業者自身が安全管理措置を講じる必要があり**、外国のサーバーにデータを保存する場合は、その国の制度などを把握する（外的環境の把握）ことが求められます。

実務上は、

- データの保管場所を**東京リージョン**に指定する（単元6-2）
- クラウド事業者の利用規約・データ処理に関する条件を確認し、顧客に説明できるようにしておく
- 個人情報の取扱いに関する公表事項（プライバシーポリシー等）の記載を、顧客が見直す必要がないか確認を促す

といった対応をとります。判断に迷う場合は、必ず最新の Q&A を確認し、専門家に相談してください。

### 6. 契約で決めておくこと

**業務委託契約**（構築・保守）や、それに付随する覚書で、少なくとも次の点を決めておきます。

| 項目 | 決めること | 決めていないと |
|---|---|---|
| **業務の範囲** | 何をやり、何をやらないか。データ移行の範囲、対応するデータ源 | 「これも入っていると思っていた」という紛争 |
| **契約の形態** | 成果物の完成を約束する（請負）か、業務の遂行を約束する（準委任）か | 責任の範囲・支払い条件の認識違い |
| **個人データの取扱い** | 利用目的の限定（目的外利用の禁止）、安全管理措置、**再委託の条件**、**事故時の報告義務**、**契約終了時のデータの返却・削除**、監査への協力 | 委託元の監督義務を果たせない。顧客の信頼を得られない |
| **秘密保持** | 業務で知った情報の扱い | |
| **権利の帰属** | 作ったプログラム・SQL・設計書の著作権は誰のものか。顧客が他社に保守を引き継げるか | 契約終了時に顧客が動けなくなる（ベンダーロックイン） |
| **アカウントの所有** | クラウドのアカウント・請求先・ドメインは顧客名義（単元5-4・7-3・2-3） | 同上 |
| **損害賠償** | 賠償の範囲と上限（例：直近◯か月分の委託料） | 1件の事故で事業が立ち行かなくなるリスク |
| **契約不適合責任** | 納品後に不具合が見つかった場合の対応期間・範囲 | |

### 7. SLA：保守の「約束」を数字にする

**SLA（Service Level Agreement）** は、提供するサービスの水準を合意したものです。大企業向けのクラウドサービスでは「稼働率 99.9%」のような数字が使われますが、中小企業向けの受託保守では、次のような項目が現実的です。

| 項目 | 例 |
|---|---|
| 対応時間帯 | 平日 9:00〜18:00（夜間・休日は別料金のオプション） |
| **初動時間** | 重大障害：連絡を受けてから（または検知してから）1時間以内に第一報 |
| 復旧目標 | 重大障害：当日中の暫定復旧を目指す（**単元7-1 の RTO と整合させる**） |
| データ | RPO：最大 5 分（PITR の範囲内） |
| 定期作業 | 月次報告、四半期ごとの復旧訓練 |
| 対象外 | 顧客側の SaaS（kintone 等）の障害、顧客による設定変更に起因する障害 |

**守れない約束はしない**ことが最も重要です。特に個人や少人数で事業を始める場合、24時間365日の対応を約束するのは現実的ではありません。

## 【実務・ビジネスとの結びつき】

### これが理解できていないと起きること

| 現場の症状 | 根本原因 |
|---|---|
| 「漏えいの疑いを社内で調べているうちに、顧客への連絡が数日遅れた」 | 委託先として直ちに通知すべきことを知らなかった |
| 「契約終了後、顧客がデータを引き上げようとしたら、業者のアカウントにしかなかった」 | アカウント・データの所有者を契約で決めていなかった |
| 「軽微な不具合の修正のつもりが、無償で大規模な改修を求められた」 | 業務範囲・契約不適合責任の範囲を決めていなかった |
| 「顧客の情報システム担当から、セキュリティの質問票に答えられず失注した」 | 安全管理措置を説明する資料を用意していなかった |

### 顧客のどの課題を解決するか

- 中小企業の経営者の多くは、個人情報保護法の義務（特に委託先の監督と漏えい時の報告）を詳しく知らない。**法律上の論点を分かりやすく整理して示せる**ことは、「技術だけの業者」との大きな差別化になる。
- 契約・SLA で責任範囲を明確にすることは、**自分の事業を守る**ことでもある。

## 【理解度チェック課題】

**Q1.**
法人顧客（会社）のデータしか扱わないデータ基盤でも、個人情報保護法を意識する必要があるのはなぜですか。

**Q2.**
あなた（受託者）が顧客のデータ基盤の保守中に、不正アクセスの痕跡を発見しました。法律と契約の観点から、最初に取るべき行動は何ですか。また、そのために普段から準備しておくべきことを2つ挙げてください。

**Q3.**
業務委託契約で「個人データの取扱い」について決めておくべき項目を4つ挙げ、それぞれ決めていないとどんな問題が起きるか説明してください。
