# 単元 7-3：クラウドコスト管理と見積もり、ROI の考え方

> **この単元のゴール**
> 提案する構成の**月額ランニングコスト**を根拠を持って見積もれるようになる。顧客にとっての**投資対効果（ROI）**を数字で示し、自分のサービス価格（初期費用・保守費用）を設計できるようになる。

---

## 【概念の解説】

### 1. クラウド費用の構造

このカリキュラムの構成で、費用がかかる主な要素は次のとおりです。

| サービス | 何に課金されるか | 規模感の目安 | 下げる工夫 |
|---|---|---|---|
| **Cloud SQL（PostgreSQL）** | インスタンスの CPU・メモリ（**常時起動の時間**）、ストレージ容量、バックアップ容量 | **多くの場合、最も大きい** | データ量・同時接続数に合ったサイズを選ぶ。HA（高可用性）にすると**おおむね2倍近く**になるので、RTO（単元7-1）と相談して決める |
| **Cloud Run / Cloud Run jobs** | 処理している間の CPU・メモリ、リクエスト数 | バッチ中心なら小さい（無料枠に収まることも多い） | 常時起動の設定（最小インスタンス数）を避ける |
| **BigQuery** | クエリのスキャン量、保存量 | 正しく設計すれば小さい（単元6-2） | 必要な列だけ・パーティション・上限設定 |
| **Cloud NAT** | 稼働時間、処理したデータ量 | 小〜中 | 固定IPが本当に必要な場合だけ使う（単元2-5） |
| **ネットワーク** | 主に**インターネットや他リージョンへの送信**データ量 | 小さいことが多い | 同じリージョン（東京）にまとめる |
| **Secret Manager / Pub/Sub / Logging / Monitoring** | 利用量 | 小さいことが多い | 不要に詳細なログを大量に出さない |

価格は改定されるので、**見積もりのたびに Google Cloud の料金計算ツール（Pricing Calculator）で計算**し、計算した日付を見積書に書きます。

### 2. 見積もりの手順

**① 前提条件を言葉で書き出す**

```text
- データ量：顧客 5,000 件、受注 年間 3 万件（明細 9 万行）、過去 5 年分を移行
- 更新頻度：kintone から 1 日 4 回同期、Webhook なし
- 利用者：ダッシュボードの閲覧者 10 名、1 日数回
- 可用性：業務時間内の停止は半日まで許容（HA なし）、RPO 数分（PITR あり）
- リージョン：東京（asia-northeast1）
```

**② 前提条件から各サービスのサイズを決め、料金計算ツールで計算する**

| サービス | サイズの決め方 |
|---|---|
| Cloud SQL | 同時接続数が少なく、データが数GBなら、小さめの構成から始める。ストレージは移行データ量 ＋ 数年分の増加 ＋ 余裕 |
| Cloud Run jobs | 1回の実行時間（例：2分）× 回数（4回 × 30日）× 割り当てる CPU・メモリ |
| BigQuery | 保存量（数GB）と、ダッシュボードの1回あたりスキャン量 × 閲覧回数（単元6-2の計算方法） |

**③ 余裕を持たせて、幅で示す**

```text
月額クラウド費用（見込み）：○○円 〜 △△円
（2026年10月時点の公式価格、為替 1ドル=□□円で計算。利用量の増加や価格改定により変動します）
```

### 3. コストの事故を防ぐ

| 仕組み | 内容 | 注意点 |
|---|---|---|
| **予算アラート** | 請求先アカウントに予算を設定し、50%・90%・100% などに達したらメールで通知 | **通知するだけで、利用は止まらない** |
| **自動停止の仕組み** | 予算の通知を Pub/Sub で受け取り、プログラムで課金を止める・サービスを停止する | 止めると業務も止まる。どこまで自動にするかは顧客と相談 |
| **BigQuery の上限** | クエリごと・1日ごとのスキャン量の上限（単元6-2） | |
| **Cloud Run の最大インスタンス数** | 攻撃や暴走で無制限にスケールしないようにする（単元5-1） | |
| **ラベル** | リソースに「顧客名」「環境（本番/開発）」のラベルを付け、費用を分類して確認する | 複数案件を管理するときに必須 |
| **定期的な棚卸し** | 使っていない開発用インスタンス、古いスナップショット、不要な固定IPを削除 | 「消し忘れ」は最も多いムダ |

### 4. 顧客にとっての ROI

経営者が最終的に知りたいのは「**いくら払って、いくら得をするのか**」です。

**ROI の計算の型**

```text
ROI = （導入による年間の効果 − 年間の費用）÷ 年間の費用
```

**効果の分類**

| 種類 | 例 | 数字にしやすさ |
|---|---|---|
| **作業時間の削減** | 毎月の集計・資料作成、Excel の突き合わせ、二重入力 | **しやすい**（時間 × 人件費） |
| **ミス・手戻りの削減** | 数字の食い違いの調査、誤った請求の訂正 | 中（過去の発生件数 × 対応時間） |
| **リスクの低減** | 情報漏洩、データ消失、属人化（担当者の退職） | 難しい（発生確率 × 被害額で概算） |
| **意思決定の改善** | 売れ筋の早期把握、不採算顧客の発見 | 難しい（具体的な事例で示す） |

**計算例**

```text
【現状】
- 経理・営業事務 3 名が、毎月の売上集計と会議資料作成に 1 人あたり月 10 時間
- 時間あたりの人件費（社会保険料等を含む）を 3,000 円と仮定
  → 3 名 × 10 時間 × 3,000 円 × 12 か月 = 年間 108 万円

【導入後】
- 集計作業がほぼなくなり、確認作業のみ（1 人月 2 時間）
  → 3 名 × 2 時間 × 3,000 円 × 12 か月 = 年間 21.6 万円
- 削減効果：年間 約 86 万円

【費用】
- クラウド費用：月 ○万円 × 12 = 年間 ○万円
- 保守費用：月 ○万円 × 12 = 年間 ○万円
- 初期構築費：○○万円（3 年で償却すると年間 ○万円）
```

**効果を盛りすぎない**ことが重要です。最初は「確実に数字にできる作業時間の削減」だけで ROI を示し、リスク低減や意思決定の改善は「数字にしていない追加の効果」として添える方が、経営者に信頼されます。

### 5. 自分のサービスの価格設計

受託ビジネスとしての価格は、一般に次の3つで構成します。

| 項目 | 内容 | 考え方 |
|---|---|---|
| **初期構築費** | ヒアリング、設計、データ移行・クレンジング、構築、ダッシュボード作成、引き渡し | 作業時間の見積もり × 単価。**データ移行は不確実性が大きい**（単元4-2）ので、事前調査を別工程（有償）にするか、前提条件を明記する |
| **月額保守費** | 監視、障害対応、バックアップの確認と復旧訓練、軽微な改修、月次報告 | 対応範囲と対応時間（SLA、単元7-4）で段階を分ける（例：平日日中のみ / 夜間休日も） |
| **クラウド実費** | 顧客の Google Cloud の利用料 | **顧客のアカウント・請求先で契約してもらう**のが原則（単元5-4：データとアカウントの所有者は顧客） |

## 【実務・ビジネスとの結びつき】

### これが理解できていないと起きること

| 現場の症状 | 根本原因 |
|---|---|
| 「見積もりの3倍の請求が来たと、顧客からクレームが来た」 | 前提条件を書かずに見積もり、利用量の変動を説明していなかった |
| 「予算アラートを設定していたのに、費用が膨らみ続けた」 | 予算アラートは通知のみで、止まらないことを理解していなかった |
| 「開発用の DB を止め忘れ、半年分の費用が発生していた」 | 定期的な棚卸しをしていなかった |
| 「ROI の説明で、根拠の弱い数字を盛った結果、導入後に"話が違う"と言われた」 | 確実な効果と不確実な効果を分けていなかった |

### 顧客のどの課題を解決するか

- 中小企業の経営者は、**ランニングコストが読めないこと**を最も嫌う。前提条件 ＋ 幅のある見積もり ＋ 上限設定 ＋ 月次報告、のセットで不安を取り除ける。
- ROI を一緒に計算する過程で、顧客の業務の中で**本当に時間がかかっている作業**が明らかになり、提案の優先順位がはっきりする。

## 【理解度チェック課題】

**Q1.**
このカリキュラムの構成（Cloud SQL・Cloud Run・BigQuery 等）で、月額費用の中で最も大きくなりやすいのはどれですか。理由と、費用を下げる方法を答えてください。

**Q2.**
予算アラートを設定していても、費用が予算を大きく超えることがあるのはなぜですか。費用の事故を防ぐ仕組みを他に2つ挙げてください。

**Q3.**
次の会社について、作業時間の削減による年間の効果を計算してください。また、ROI の説明で「効果を盛りすぎない」ことが大切な理由を述べてください。
- 営業事務2名が、kintone と Excel の突き合わせに1人あたり週3時間かけている
- 時間あたりの人件費は 2,800 円
- 導入後は突き合わせが不要になる（確認のみ、1人週30分）

## 【顧客向け言語化トレーニング】

専門用語（ランニングコスト、ROI、従量課金等）を使わずに答えてください。

**演習1**
> 社長「結局、全部でいくらかかるの？ 毎月いくら？ それって元が取れるの？」

**演習2**
> 社長「他の会社に相見積もりを取ったら、もっと安かったよ。」

<details>
<summary>💡 回答のヒント（考えてから開く）</summary>

- 演習1：3つに分けて答える。「最初に一度だけかかる費用」「毎月かかる費用（Google への支払い・私たちの保守）」「それによって毎月浮く作業時間とその金額」。「○か月で元が取れる計算です」と、回収期間で示すと伝わりやすい。根拠となる前提（作業時間など）は社長と一緒に確認した数字を使う。
- 演習2：値下げで応じる前に、見積もりの「範囲」を比べることを提案する。データ移行・クレンジングは含まれているか、セキュリティ対策は何をしているか、保守で何をしてくれるか、障害時の対応時間は、クラウドのアカウントは誰の名義か。同じものを比べた上で判断してほしい、と伝える。他社を悪く言わない。
