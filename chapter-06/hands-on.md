# 第6章 ハンズオン：BigQuery に分析基盤を作り、Looker Studio で経営ダッシュボードを公開する

> **目的**：raw → staging → mart の3層を実際に作り、品質チェックを通したデータで、経営ダッシュボードを完成させる。
> **所要時間**：3〜4時間
> **必要なもの**：Google アカウント（**クレジットカード不要**の BigQuery サンドボックスを使う）
> **使うファイル**：[`lab/`](./lab/) フォルダ一式

```text
lab/
├── generate_data.py         サンプルデータの生成スクリプト（生成済みの CSV も同梱）
├── data/                    raw 層に入れる CSV（PostgreSQL から取り出した想定）
│   ├── raw_orders.csv       受注（同じ注文の「受付時」と「出荷後」の版が両方入っている）
│   ├── order_items.csv      受注明細
│   ├── customers.csv / products.csv / staff.csv
└── sql/
    ├── 01_staging.sql       raw → staging（重複除去・型変換）
    ├── 02_mart.sql          staging → mart（スター・スキーマ ＋ 横長の表）
    ├── 03_quality_checks.sql 品質チェック
    └── 04_analysis.sql      分析とコストの観察
```

> **BigQuery サンドボックスについて**：Google アカウントだけで使える無料の環境です。保存 10GB・クエリ月 1TB まで、テーブルは 60 日で自動的に期限切れになる、データの更新系 SQL（INSERT / UPDATE / MERGE）やスケジュール実行は使えない、などの制限があります（最新の条件は公式ドキュメントで確認してください）。このハンズオンは、その範囲で完結するように作ってあります。

2. 案内に従って、新しいプロジェクトを作成する（例：`data-platform-lab`）。課金の設定は不要
3. 画面上部に「サンドボックス」と表示されていれば準備完了

## ステップ1：データセットを作り、CSV を raw 層に入れる（単元6-2・6-3）

### 1-1. データセットを3つ作る

左側のエクスプローラで、プロジェクト名の横の「︙」→「データセットを作成」。

| データセット ID | ロケーション |
|---|---|
| `raw` | **リージョン → asia-northeast1（東京）** |
| `staging` | 同上 |
| `mart` | 同上 |

> ロケーションは**作成後に変更できません**（単元6-2）。3つとも必ず同じロケーションにしてください（異なるロケーションのデータセット同士は JOIN できません）。

### 1-2. CSV をアップロードしてテーブルを作る

`raw` データセットの「︙」→「テーブルを作成」で、5つのファイルを順にアップロードします。

| 設定項目 | 値 |
|---|---|
| テーブルの作成元 | アップロード |
| ファイルを選択 | `lab/data/raw_orders.csv` など |
| ファイル形式 | CSV |
| テーブル | 下表のテーブル名 |
| スキーマ | **自動検出** にチェック |

| ファイル | テーブル名 |
|---|---|
| `raw_orders.csv` | `orders` |
| `order_items.csv` | `order_items` |
| `customers.csv` | `customers` |
| `products.csv` | `products` |
| `staff.csv` | `staff` |

作成後、`raw.orders` を選んで「プレビュー」タブを開きます（**プレビューは無料**。単元6-2）。同じ `id` の行が2つずつある（`received` と `shipped`）ことを確認してください。

## ステップ3：mart を作る（単元6-4）

[`lab/sql/02_mart.sql`](./lab/sql/02_mart.sql) を貼り付けて実行します。

```sql
-- 日付ディメンションの確認：会計年度・四半期が正しいか
SELECT date, fiscal_year, fiscal_quarter, weekday_ja
FROM mart.dim_date
WHERE date IN ('2025-03-31', '2025-04-01', '2025-07-01', '2026-01-05')
ORDER BY date;
```

2025-03-31 は **2024年度の第4四半期**、2025-04-01 は **2025年度の第1四半期** になっていれば正解です。

## ステップ4：品質チェック（単元6-3）

[`lab/sql/03_quality_checks.sql`](./lab/sql/03_quality_checks.sql) を実行し、**すべての行で `ok` が `true`** になっていることを確認します。

**JOIN の誤りで行が増える事故を見てみる**：明細単位の `fct_sales` に、同じく明細単位の `order_items` を「注文 ID だけ」で結合すると、1注文に複数の商品がある場合に行が掛け算で増えます。

```sql
SELECT
  (SELECT COUNT(*) FROM mart.fct_sales) AS correct_rows,
  (SELECT COUNT(*)
     FROM mart.fct_sales AS f
     JOIN staging.order_items AS i ON i.order_id = f.order_id) AS wrong_rows,   -- product_id での結合を忘れた
  (SELECT SUM(f.amount)
     FROM mart.fct_sales AS f
     JOIN staging.order_items AS i ON i.order_id = f.order_id) AS wrong_sales;   -- 売上も水増しされる
```

チェック5（fct_sales と sales_wide の行数の一致）は、mart を作るときにこの種の誤りが紛れ込んでいないかを、毎回自動で確かめるためのものです。

## ステップ6：Looker Studio でダッシュボードを作る（単元6-5）

### 6-1. データソースをつなぐ

1. [Looker Studio](https://lookerstudio.google.com/) を開き、「空のレポート」を作成
2. コネクタで **BigQuery** を選び、「マイプロジェクト」→ 作ったプロジェクト → `mart` → **`sales_wide`** を選んで追加
3. レポートの編集画面で、メニューの「リソース」→「追加済みのデータソースの管理」→ `sales_wide` の「編集」を開き、次を確認する
   - `order_date` のタイプが「日付」になっている
   - `amount` の集計方法が「合計」になっている
   - **データの認証情報**が「オーナー」になっている（ステップ7で扱います）

### 6-2. レイアウト（単元6-5 の「結論 → 推移 → 内訳 → 明細」）

| 位置 | グラフ | 設定 |
|---|---|---|
| 最上部 | **期間設定** コントロール | 既定の期間：2025-04-01〜2026-03-31（2025年度） |
| | **プルダウンリスト** コントロール | ディメンション：`department` |
| ① | **スコアカード** × 3 | 指標：`amount`（売上）、`order_id` のカウント（個別）（受注件数）、`customer_name` のカウント（個別）（取引顧客数）。**比較期間：前年** |
| ② | **期間グラフ**（折れ線） | ディメンション：`order_date`（月単位）、指標：`amount`、比較期間：前年 |
| ③左 | **棒グラフ** | ディメンション：`product_category`、指標：`amount` |
| ③右 | **棒グラフ** | ディメンション：`staff_name`、指標：`amount` |
| ④ | **表** | ディメンション：`customer_name`、`customer_rank`、指標：`amount`、`order_id`（個別のカウント）。`amount` の降順、20行 |

**レポート全体のフィルタ**：「ファイル」→「レポートの設定」→ フィルタを追加 → `is_valid_sale` が `true` のものを含める。これで**キャンセルを除いた売上**の定義がすべてのグラフに一律に適用されます（単元6-4の「定義は1か所で」）。

### 6-3. 仕上げ

- 各スコアカードの名前を「売上（税抜・キャンセル除く）」のように、**定義が分かる名前**にする
- テキストボックスで「データの更新：毎日 6:00」「売上の定義：受注日ベース・税抜・キャンセル除く」と注記する

## ステップ7：共有設定とデータの認証情報（単元6-5）

1. 右上の「共有」を開く。**「リンクを知っている全員」になっていないこと**を確認する
2. 自分の別のアカウント（または信頼できる友人）を「閲覧者」として追加し、そのアカウントで開けることを確認する
3. データソースの「データの認証情報」を「**閲覧者**」に切り替え、もう一度そのアカウントで開いてみる → BigQuery の権限がないため、**データが表示されない**ことを確認する
4. 確認したら「オーナー」に戻す

**考察**：手順3で表示されなかった理由と、「オーナー」「閲覧者」のどちらを選ぶべきかを、顧客の状況（社員10名で全員が全社の数字を見てよい会社 / 部署ごとに見せる数字を変えたい会社）ごとに考えてください。
